## 2. Algorithm pinned from evidence

.NET 10.0.3; the test project targets net10.0. A seeded Random(int) does **not** use the parameterless constructor's Xoshiro256** implementation. Random.cs sends the base type to CompatSeedImpl, whose CompatPrng is the historical modified-Knuth subtractive generator, kept exactly so seeded sequences remain compatible:

- https://github.com/dotnet/runtime/blob/release/10.0/src/libraries/System.Private.CoreLib/src/System/Random.cs — public Random(int Seed)
- https://github.com/dotnet/runtime/blob/release/10.0/src/libraries/System.Private.CoreLib/src/System/Random.CompatImpl.cs — CompatSeedImpl, CompatPrng.Initialize, InternalSample, Sample, GetSampleForLargeRange

The exact seeding and sample arithmetic:

    int subtraction = (seed == int.MinValue) ? int.MaxValue : Math.Abs(seed);
    int mj = 161803398 - subtraction;          // seedArray[0] is unused
    seedArray[55] = mj;
    int mk = 1;
    int ii = 0;
    for (int i = 1; i < 55; i++) {
        if ((ii += 21) >= 55) ii -= 55;
        seedArray[ii] = mk;
        mk = mj - mk; if (mk < 0) mk += int.MaxValue;
        mj = seedArray[ii];
    }
    for (int k = 1; k < 5; k++)
        for (int i = 1; i < 56; i++) {
            int n = i + 30; if (n >= 55) n -= 55;
            seedArray[i] -= seedArray[1 + n];
            if (seedArray[i] < 0) seedArray[i] += int.MaxValue;
        }
    _inext = 0; _inextp = 21;

    int InternalSample() {
        int a = _inext + 1; if (a >= 56) a = 1;
        int b = _inextp + 1; if (b >= 56) b = 1;
        int ret = seedArray[a] - seedArray[b];
        if (ret == int.MaxValue) ret--;
        if (ret < 0) ret += int.MaxValue;
        seedArray[a] = ret; _inext = a; _inextp = b;
        return ret;
    }
    double Sample() => InternalSample() * (1.0 / int.MaxValue);

Next(max) truncates Sample() * max toward zero; Next(min,max) truncates Sample() * ((long)max - min) and adds min (the large-range branch is also ported). NextDouble is Sample().

### 4.1 The four blockers, exactly

**Row 1 — no Expr interning; canonical text not idempotent for one item.** Context interns Symbol and FunctionId (context.rs:10-12, 356-383), not Expr; Expr is a value enum, so Assert.Same has no Rust spelling. The nearest executable property also fails on one generated item. For canonical item 49:

    C#    : (mul (add (rat -5 1) (mul (rat -1 1) (fn sin (mul (rat 2 1) (sym x))))) (add (fn exp (fn abs (sym x))) (fn exp (add (rat -5 1) (sym x)))))
    Rust  : (mul (add (fn exp (fn abs (sym x))) (fn exp (add (rat -5 1) (sym x)))) (add (rat -5 1) (mul (rat -1 1) (fn sin (mul (rat 2 1) (sym x))))))
    Rust after parse+print:
            (mul (add (rat -5 1) ...) (add (fn exp ...) ...))   -- the first ordering, not the second

**Row 3 — numeric::evaluate refuses relations and piecewise.** The generated derivative contains (mul (rat -1 1) (pw ((ne (fn sin (rat -1 1)) (rat 0 1)) (rat 0 1)) (fn derivative))). lovelace-lang/src/numeric.rs:70-72 returns "A relation has no numeric value; evaluate a number or an expression." The reference Evaluation.EvaluateToNum handles PiecewiseExpr (Evaluation.cs:487-499) and RelationExpr via EvaluateCondition (Evaluation.cs:572-617). This needs a production numeric arm.

**Row 4 — integration misses the u-substitution shape.** The C# probe returns a closed form for all six integrands (SymbolExpr, AddExpr, MultiplyExpr, FunctionExpr, FunctionExpr, MultiplyExpr). Rust returns unevaluated for integrand 5, (mul (fn sin (pow (sym x) (rat 3 1))) (pow (sym x) (rat 2 1))), so the C# closed-form round trip cannot be asserted. The integration kernel is builtins.rs:1463 / integrate_basic at builtins.rs:6392; the missing case is a production builtins change.

**Row 7 — numeric and IR evaluators differ by one ulp.** For (add (rat 5 3) (mul (rat -1 1) (add (fn sin (sym x)) (mul (rat -1 1) (fn exp (sym x))))) (mul (rat 2 1) (sym x))) at x=1/3:

    direct  : 340175106162327061778811456766829956486693844163898e-50
    lowered : 340175106162327061778811456766829956486693844163897e-50

The reference asserts exact NumOps.Compare(direct, lowered) == 0, so a tolerance would weaken the row. This is a production numeric/IR parity gap.
