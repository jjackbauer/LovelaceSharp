## 2. How each row was verified

### 2.1 The printing cluster (145 rows)

Round 16 implemented `CanonicalParse`, `DebugPrint` and print-mode dispatch and verified them
against the oracle on 28 expressions. What was missing was the counted mapping: the census rows
were still `deferred` with the round-11 reason. The new module transcribes each C# theory's own
corpus **in theory-data order**, with the census case index as the first tuple element, and asserts
the C# assertion for that row:

* **Canonical (48).** `PrettyParenthesesTests.cs:218` asserts
  `CanonicalPrint(CanonicalParse(canonical, ctx)) == canonical` and
  `PrettyPrint(expr, PrintOptions(Canonical)) == canonical`. Rust:
  `canonical_parse(&canonical)?.canonical() == canonical` and
  `expr.print(PrintMode::Canonical) == canonical`.
* **Debug (48).** `PrettyParenthesesTests.cs:229` asserts
  `PrettyPrint(expr, PrintOptions(Debug)) == DebugPrint(expr)` and `!debug.Contains("((")`. Rust:
  `expr.print(PrintMode::Debug) == expr.debug_print()` and the same substring ban, per row.
* **Dispatch (49).** `LatexPrinterTests.cs:312` asserts Canonical is `CanonicalPrint`, Debug is
  `DebugPrint`, `Print(expr, PrintOptions(Latex)).Text` is the LaTeX rendering, and the Canonical
  text starts with `(`. Rust asserts the same four claims with `expr.print(PrintMode::…)`.
  The corpus includes `abs(...)`, `x^(-1/2)` and `(x/y)/(z/w)`. Two of its rows carry a known
  pretty-rendering divergence, but the dispatch assertion is mode coherence, which was verified for
  all 49 rows; nothing is assumed from a neighbouring row.

The corpus tables were generated from `parity/census.json` `displayName` arguments and
cross-checked: the 48-row table is identical for the Canonical and Debug theories, the 49-row table
matches `LatexPrinterTests.Corpus`, and every `#N` id maps to index N. The oracle-canonical
divergences of two rows (`integrate_full(exp(-x^2), x)`, `diff(exp(x)*x^2, x)`) do not affect
these rows: the C# assertion is self-consistency of the canonical codec, not oracle equality.

### 2.2 The adjacent rows (19)

* **Print budgets (8 rows).** `PrintBudgetTests` (5) and `PrintBudgetTokenBoundaryTests` (2) are
  C# facts over `Printing.Print(expr, PrintOptions(Budget: …))`. This crate has no kernel budget
  object; its **budgeted rendering is the structured wire projection**
  (`structured::project_value(engine, value, Some(nodes))`), which publishes `pretty`,
  `canonical`, `nodeCount`, and — when the node budget bites — `truncated`,
  `truncationReason = "node-budget"` and `budget`. The Rust tests assert the same observable
  claims on that projection: no-budget and over-large-budget are the whole rendering; the node
  budget reports reason/count/budget and a strict `" …"` prefix; the canonical arm honours the
  same budget; a cut never lands inside a token; one long token retains nothing. The C# fact's
  own policy statement (a compact rendering the character allowance holds whole is left whole) is
  *not* reproduced by the projection and is refused (§3) rather than restated.
* **Run.Tests budget rows (8 rows).** `PrintBudgetTotalityTests` (7) and
  `PrintBudgetTokenBoundaryTests` (1) target the same projection at the runner's
  `--print-budget` seam. The Rust tests drive the projection directly and prove the stated
  property over all six generated node counts and every budget below/at/above them, plus the
  54-/40-character identifier boundary rows that the projection's proportional allowance can reach.
  One totality row (the envelope-variable one) and two token-boundary rows are refused in §3.
* **Four single rows.** The Dx fraction-coefficient rendering (`-1/2/(x + 1)`, `x/x`, `2/x`),
  the usage snippet (`x^2 + 2*x + 1`), the kernel's `(x^y)^2` structural preservation plus its
  rendering, and `TermOrder`'s antisymmetry/numbers-first property over `canonical_order`. Each
  expected value is the C# assertion transcribed from source.

## 5. What could not be verified

- **The C# tests were not executed.** The VSTest testhost cannot run in this environment
  (`parity/README.md`); every expected value is the C# assertion transcribed from source, and every
  Rust assertion was executed green. One of the 17 tests (the node-count totality test) proves a
  property over six generated node counts and every budget below/at/above each, exactly as its C#
  theory does; the other 16 assert fixed rows or fixed expressions.
- **The 220 target was not met: 164 rows.** §3 is the measured accounting; the shortfall is
  concentrated in the 29 refused rows above.
- **The print-budget rows are ported through the structured projection**, not through a kernel
  `PrintOutcome` (the crate has none). The projection is the same rendering surface the runner
  publishes and carries the same outcome fields; the two policy assertions that differ between the
  kernel and the projection are among the refusals, not silently accepted.
- **No production change was made**, by scope; the pretty-printer divergences of §3.1 and the
  absent kernel budget/depth API are the production gaps this batch measured.
- The pre-existing corpus failures (`sym/071`, `sym/076`) are unchanged and are not caused by this
  batch (they are the round-12 baseline).
