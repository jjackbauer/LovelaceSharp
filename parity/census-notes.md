# C# test census — method, totals, and reconciliation

Artifact: `parity/census.json` (schemaVersion 1), generated by
`parity/tools/census` (a net10.0 console project with **no** PackageReference).
Frozen oracle: commit `1cc28f255eca6029849f880949fc7be1d40ab8af` (branch `rust`),
`capturedAtUtc = 2026-11-10T14:39:48Z`, both copied from `parity/oracle.json`.

## 1. What the census counts

The tool loads each test project's built assembly
(`<project>/bin/Debug/net10.0/<project>.Tests.dll`) into an isolated
`AssemblyLoadContext` and reflects over every type and method. A method is a test
method when one of its attributes derives from `Xunit.FactAttribute`
(`Xunit.TheoryAttribute` derives from it, so it is classified as a theory first).

* **factMethods** — methods carrying a Fact-derived attribute (including custom
  subclasses such as `RequiresRunnerProcessFactAttribute` and
  `RequiresSympyFactAttribute`). Each contributes exactly one case, `dataKind = "fact"`.
* **theoryMethods** — methods carrying a Theory attribute. Each data attribute is
  enumerated by invoking the attribute's own public
  `DataAttribute.GetData(MethodInfo)` implementation — the same entry point xunit
  uses — so `InlineData` and `MemberData` rows are expanded exactly as the framework
  would expand them.
* **inlineDataRows** — one row per `[InlineData(...)]` row, `dataKind = "inline"`.
* **memberDataRows** — one row per item produced by each `[MemberData(nameof(X))]`
  source, `dataKind = "member"`.
* **dataUnavailable** — a theory whose data could not be enumerated is emitted as
  **one** row with `dataUnavailable: "<reason>"` and counted here. Nothing is dropped
  silently. The final run has **0** refusals.
* `caseIndex` is 0-based within (project, fully-qualified class, method); the id is
  `project/class/method#caseIndex`, and cases are sorted by id (ordinal).

The tool reproduces the xunit testhost environment per project before invoking data
sources: it sets `AppDomain.CurrentDomain.SetData("APP_CONTEXT_BASE_DIRECTORY", <test output dir>)`
and the current directory to the test output directory. This matters:
`LanguageDocumentationTests.Examples` reads `Language.md` via
`AppContext.BaseDirectory` (`Lovelace.Suite.Tests/LanguageDocumentationTests.cs:16`)
and `UsageDocumentationTests.Examples` reads `README.md` the same way
(`Lovelace.Symbolics.Tests/UsageDocumentationTests.cs:16`). Without that setup both
theories were reported as unavailable; with it they contribute 111 and 103 rows.

## 3. Reconciliation with the reference figures

The request fixed three source-occurrence figures to reconcile against, and the
specification's reference count of 2,087 test facts
(`docs/parity/contract-v2.md:64`). An independent source scan over the 15 test
project directories (all `.cs`, excluding `bin`/`obj`) reproduces those figures
exactly:

| figure | source count | census | explanation |
|---|---:|---:|---|
| `[Fact]` text occurrences | 1,904 | — | one of them is prose in a doc comment (`Lovelace.Run.Tests/FalsificationGateTests.cs:743`); 1,903 are real attribute declarations |
| fact methods | 1,903 plain + 19 custom | 1,922 | 19 methods use `[RequiresRunnerProcessFact]` (11) or `[RequiresSympyFact]` (8), both `FactAttribute` subclasses, which xunit discovers as facts; a literal `[Fact` scan cannot see them |
| `[Theory]` occurrences | 183 | 183 | exact match (135 inline-only theories, 48 member-data-only theories, 0 mixed) |
| `[InlineData]` occurrences | 709 | 709 | exact match |
| `[MemberData]` occurrences | 48 | 48 theories | 3,578 expanded rows |

**Why `testCases` is 6,209 and not 2,087.** 2,087 = 1,904 + 183 counts each
`[Theory]` as **one** case. The census expands theory data rows, as required
("enumerate THEORY DATA ROWS, not just methods"): the 183 theories produce
709 inline rows + 3,578 member-data rows = 4,287 cases. 1,922 fact cases + 4,287
theory-data cases = 6,209.

The difference between `testMethods` (2,105) and 2,087 is exactly +18: −1 for the
doc-comment `[Fact]` that is not a method, +19 for the custom `FactAttribute`
subclasses. Both numbers are computed from the assemblies, not hardcoded.

## 4. Determinism

`capturedAtUtc` is **pinned**, not sampled at generation time: the tool reads
`commit` and `capturedAtUtc` from `parity/oracle.json` (and accepts an explicit
`--captured-at` override). Everything else is derived from the assemblies and source
text. Two consecutive runs produced byte-identical files:

```
SHA256 run 1: 3cb60e8cc20896999341f25f2f64ecb2584d780187816245844f96309786be02
SHA256 run 2: 3cb60e8cc20896999341f25f2f64ecb2584d780187816245844f96309786be02
```

No hashes of runtime state enter the file. Case ids are
`<project>/<fully-qualified class>/<method>#<caseIndex>`.

## 5. Source locations

`sourceFile` is repository-relative with forward slashes; `sourceLine` is:

* the first visible sequence point from the portable PDB beside the assembly (for a
  synchronous method this is normally the opening-brace line, i.e. the signature line
  + 1) — 1,544 methods in the final run; or
* the declaration line found by a deterministic source scan — 561 methods, mostly
  `async` tests whose PDB kickoff method has no visible sequence point.

0 methods had no location. The scan is limited to the method's own project directory
and requires the class declaration and a `[Fact`/`[Theory`-style attribute above the
declaration.

## 6. Refusals

The mechanism is exercised and honest: when a `MemberData` source throws, the tool
discards any partially enumerated rows and emits one row for the theory with
`dataUnavailable = "<attribute> failed: <exception type>: <message>"`; the same happens
for a theory with no data attribute or a data attribute that yields zero rows. The
final run has `dataUnavailable = 0`, so every one of the 183 theories is represented
by real data rows.

## 7. Reproduction order (important)

The census reads build outputs. The pre-existing `bin/Debug/net10.0` assemblies were
older than some sources (for example `Lovelace.Symbolics.Tests` DLL was from
2026-09-12 while its newest source was 2026-09-16), so all 15 test projects were
rebuilt at the frozen commit before the census was taken:

```
dotnet build <project>/<project>.csproj -c Debug      # for each of the 15 *.Tests projects
dotnet build parity/tools/census/census.csproj -c Release
dotnet exec parity/tools/census/bin/Release/net10.0/census.dll --repo <repo root>
```

The tool fails (exit 1) if an assembly is missing; it does **not** detect a stale
assembly. Rebuild the test projects before regenerating `census.json`.

## 8. Known limitations / not verified

* Tests were never executed: `dotnet test` cannot run here (testhost is denied).
  The census is a static/reflection inventory, not a pass/fail record. Every test is
  counted regardless of `Skip` (custom fact attributes set `Skip` when the runner
  assembly is absent).
* xunit's own discovery filters (public non-abstract class, method not generic, etc.)
  are not re-implemented. In this repository all 281 test classes are `public` and no
  test class is `abstract`, so no case is excluded by that difference.
* `dataKind` only knows `fact`, `inline`, `member`. No `[ClassData]` or custom
  `DataAttribute` subclass exists in the 15 projects; the tool fails closed if it ever
  meets one, rather than miscounting it.
* PDB-derived `sourceLine` values point at the method body's first sequence point,
  not at the signature line; scan-derived values point at the declaration line.
